# Гайд по защите проекта Bookstore

## Что это за проект и зачем ты его сделал?

Это веб-приложение для чтения книг. Пользователь загружает PDF или EPUB, приложение сохраняет файл, запоминает прогресс чтения, позволяет делать заметки, выделять текст хайлайтами и общаться с AI-ассистентом по содержимому книги.

Я хотел сделать что-то практичное — читалку, которую не нужно устанавливать, она работает в браузере и хранит всё в одном месте. Интеграция с AI добавляет ценность: можно задать вопрос прямо по книге которую читаешь.

---

## Расскажи про технологический стек, почему именно это?

**Next.js 16** — потому что он объединяет фронтенд и бэкенд в одном проекте. API Routes прямо внутри приложения, не нужен отдельный сервер. App Router даёт серверные компоненты и удобную структуру папок.

**React 19** — последняя версия, стабильная поддержка hooks и concurrent features.

**Tailwind CSS 4** — быстрая вёрстка без написания отдельных CSS-файлов.

**SQLite + Prisma** — SQLite идеален для локального проекта, не нужен отдельный сервер БД. Prisma даёт типизированный клиент и миграции.

**NextAuth v5** — стандарт аутентификации в экосистеме Next.js, поддерживает JWT-сессии.

## Как работает аутентификация?

1. Пользователь заходит на `/register`, вводит email и пароль
2. Пароль хэшируется через `bcryptjs` (10 раундов соли) и сохраняется в БД — пароль в открытом виде нигде не хранится
3. При логине — пароль сравнивается с хэшем через `bcrypt.compare`
4. NextAuth создаёт JWT-токен, сохраняет в httpOnly cookie
5. `middleware.ts` перехватывает каждый запрос и проверяет наличие сессии. Если нет — редирект на `/login`

Публичные маршруты (без авторизации): `/login`, `/register`, `/api/auth/*`

## Как загружаются и хранятся файлы?

Пользователь перетаскивает PDF или EPUB на зону загрузки или выбирает через диалог.

Фронтенд отправляет `multipart/form-data` POST на `/api/books`.

Бэкенд:
1. Проверяет расширение файла (только pdf/epub) и размер (макс 100 МБ)
2. Генерирует уникальный UUID для имени файла
3. Создаёт папку `uploads/<userId>/` если её нет
4. Записывает файл на диск через Node.js `fs.writeFile`
5. Извлекает превью-текст (первые ~500 символов) для AI-контекста
6. Через AI генерирует чистый заголовок из имени файла (убирает "_", "-", теги, номера)
7. Создаёт запись в БД

## Как читаются PDF и EPUB — это же разные форматы?

**PDF**: используется библиотека `pdfjs-dist` (от Mozilla). Она рендерит каждую страницу в canvas/DOM-элемент. У меня два режима:
- `scroll` — все страницы рендерятся одновременно, пользователь скроллит
- `paged` — показывается одна страница, навигация кнопками

**EPUB**: это ZIP-архив внутри. Я написал собственный парсер:
1. Распаковываю ZIP через `JSZip`
2. Читаю `META-INF/container.xml` — там указан путь к `content.opf`
3. Из `content.opf` извлекаю `spine` — порядок глав
4. Каждая глава — XHTML-файл. Парсю через `@xmldom/xmldom`
5. HTML главы возвращается через API и рендерится в `<iframe>`

## Как работает AI-ассистент?

В ридере есть боковая панель с чатом. Пользователь пишет вопрос, он уходит на `/api/ai/chat`.

Бэкенд строит промпт:
```
You are a helpful reading assistant.
Book: [название книги]
Context: [первые 1000 символов prevewText или текущей страницы]
Question: [вопрос пользователя]
```

Запрос идёт в **OpenRouter API** — это агрегатор AI-моделей, там можно использовать GPT, Claude, Llama через единый API. Я использую бесплатную модель по умолчанию.

История чата хранится в таблице `Message` с полем `role` (user/assistant), как в ChatGPT.

## Как сохраняется прогресс чтения?

Прогресс сохраняется автоматически, пользователь ничего не нажимает.

В компоненте `Reader.tsx`:
- При смене страницы запускается таймер 800ms (дебаунс). Если за 800ms страница не изменилась — отправляется запрос `POST /api/books/[id]/progress`
- При закрытии вкладки — отправляется финальный запрос с флагом `keepalive: true` (браузер не обрывает его при закрытии)
- Время чтения считается через `Date.now()`: запоминаем начало, при каждом сохранении прогресса считаем дельту в минутах
- Создаётся `ReadingEvent` с количеством страниц и минут — для статистики

Статус книги: `not_started` → `reading` → `completed` (автоматически при 100%)

## Что такое хайлайты и как они работают?

Пользователь выделяет текст мышкой в ридере → браузер создаёт `Selection` объект. Через `window.getSelection().toString()` я получаю выделенный текст и вставляю его в поле формы.

Дальше пользователь выбирает цвет (жёлтый, зелёный, синий, розовый) и сохраняет. Хайлайт сохраняется в БД с номером страницы. В боковой панели все хайлайты показываются со ссылкой — кликнул на номер страницы, прыгнул туда.

## Расскажи про статистику и цели

Страница `/stats`:
- **Книги всего** — `prisma.book.count`
- **Завершено** — `progress.status === 'completed'`
- **Страниц прочитано** — сумма всех `progress.currentPage`
- **Средний прогресс** — среднее значение `progress.percentage`

**Дневная цель** — пользователь сам ставит: "20 страниц в день" или "30 минут". Прогресс считается из `ReadingEvent` за текущий день (от 00:00).

**Уведомление**: если последний `ReadingEvent` был больше 24 часов назад — показывается напоминание "Вы не читали X часов".

## Как устроены настройки ридера?

Настройки хранятся в таблице `Preferences` (1 строка на пользователя).

При изменении любой настройки на странице Settings:
1. Локальный state обновляется мгновенно (UI не лагает)
2. `PATCH /api/preferences` отправляется в фоне
3. В следующий раз при открытии ридера настройки загружаются с сервера

Тема влияет на цвет фона, текста, панели. Три темы: light, dark, sepia. Все компоненты ридера принимают объект `theme` с цветами и применяют через inline styles.

## Какие технические решения тебя удивили или были сложными?

**Самописный EPUB-парсер** — готовых Next.js-совместимых библиотек не было. Пришлось разобраться в спецификации формата: container.xml → content.opf → spine → XHTML глав.

**Отслеживание страницы в режиме scroll** — нельзя просто взять номер страницы, нужно смотреть на положение скролла. Решил через атрибуты `data-page-number` на DOM-элементах страниц и `requestAnimationFrame`.

**keepalive при закрытии вкладки** — обычный `fetch` в `useEffect cleanup` не отрабатывает при закрытии браузера. Флаг `keepalive: true` позволяет браузеру завершить запрос даже после ухода со страницы.

**AI-очистка заголовков книг** — файлы часто называются типа `the_great_gatsby_scan_2019_fixed.pdf`. При загрузке AI автоматически преобразует это в нормальное название. Для старых книг — фоновая дообработка при первом запросе библиотеки (fire-and-forget через `Promise.allSettled`).

## Вопросы по безопасности

**Как защищены данные пользователей?**
- Пароли — только bcrypt-хэши, никогда не хранятся в открытом виде
- Каждый API-запрос проверяет `userId` из сессии. Нельзя получить чужую книгу, даже зная её `id`
- Загружаемые файлы проверяются по расширению и размеру

**SQL-инъекции?**
- Prisma использует параметризованные запросы, SQL-инъекции исключены

**XSS в EPUB?**
- При парсинге EPUB (в `lib/epub.ts`) HTML очищается: удаляются все теги `<script>`, `<iframe>`, `<object>`, `<embed>` и инлайн-обработчики событий (`onload`, `onclick` и т.д.). Содержимое рендерится безопасно.

## Вопросы по архитектуре

**Почему не использовал Redux/MobX?**
Состояние каждой страницы локальное — библиотека, ридер, настройки не делятся состоянием между собой. Хватает `useState` и `useCallback`. Zustand подключён в зависимостях но не использовался — оказалось ненужным.

**Почему SQLite а не PostgreSQL?**
Для локального запуска SQLite идеален — нет зависимости от внешнего сервера. При необходимости Prisma позволяет переключить провайдер на PostgreSQL заменив одну строку в `schema.prisma`.

**Почему Next.js App Router а не Pages Router?**
App Router — современный подход, поддерживает серверные компоненты (RSC), что уменьшает JS на клиенте. Страницы ридера частично рендерятся на сервере.
